# Проектная работа 7 спринта: RAG-бот для QuantumForge Software

## Задание 1. Исследование моделей и инфраструктуры

**1. Сравнение LLM-моделей (локальные Hugging Face против облачных OpenAI / YandexGPT)**

| Параметр | Локальные модели (Hugging Face) | Облачные модели (OpenAI, YandexGPT) |
|---|---|---|
| **Качество ответов** | Высокое, зависит от модели (Llama 3.1, Mistral, Qwen); возможна донастройка под домен | Очень высокое, особенно у GPT-4, YandexGPT Pro, Claude 3.5 |
| **Скорость работы** | Зависит от ресурсов, требуется оптимизация; возможна задержка при inference | Высокая, предсказуемая; зависит от latency API |
| **Стоимость владения** | CapEx (сервера, лицензии), эксплуатация | OpEx (плата за API), без инфраструктурных затрат |
| **Простота развёртывания** | Требует ML-инфраструктуру, DevOps навыки | Готовый API, SDK, быстрое внедрение |

**Вывод:**  
Для пилотных проектов и быстрого старта — облачные модели более просты и быстрее в реализации. Для масштабных решений и контроля данных — локальные модели более выгодны.

**2. Сравнение моделей эмбеддингов (локальные Sentence-Transformers vs облачные OpenAI/Yandex)**

| Параметр | Локальные Sentence-Transformers | Облачные (OpenAI, Yandex) |
|---|---|---|
| **Скорость создания индекса** | Быстрая, зависит от GPU (например, BGE-M3) | Быстрая, API-зависимо |
| **Качество поиска** | Хорошее, возможность дообучения под домен | Отличное, особенно в англоязычных данных |
| **Стоимость владения** | Минимальные операционные затраты, инфраструктура | Оплата за вызовы API, переменная стоимость |

**Вывод:**  
Для внутренней документации, особенно при необходимости высокой безопасности, предпочтительна локальная генерация эмбеддингов. Для быстрого пилота или менее чувствительных данных — облачные сервисы.

**3. Сравнение векторных баз: ChromaDB и FAISS**

| Параметр | FAISS | ChromaDB |
|---|---|---|
| **Скорость поиска и индексации** | Очень высокая, масштабируемость до миллионов векторов | Хорошая, подходит для до 500К векторов, удобство использования |
| **Сложность внедрения и поддержки** | Требует интеграции, настройка, требуется отдельный сервис | Готовое решение, SDK, API, простота поддержки |
| **Удобство работы** | Минималистичный API, высокая производительность | Гибкий API, поддержка метаданных, фильтрации |
| **Стоимость владения** | Открытый исходный код, инфраструктура зависит от масштабов | Аналогично — бесплатное ПО, затраты на инфраструктуру |

**Вывод:**  
FAISS — для высокой скорости и больших объемов, требует больше усилий по интеграции.  
ChromaDB — для быстрой разработки, поддержки метаданных, подходит для прототипирования и небольших/средних объемов.

**4. Рекомендуемая конфигурация сервера**

| Вариант | CPU | RAM | GPU | Хранилище | Комментарии |
|---|---|---|---|---|---|
| **A. Облачный** | — | — | OpenAI API + облачные базы | — | Быстрый старт, без инфраструктурных затрат, качество GPT-4 |
| **B. Гибридный** | 16–32 vCPU | 128 ГБ | 1× NVIDIA H100 / A40 | 2–4 ТБ NVMe | Контроль данных, баланс стоимости и скорости |
| **C. On-premise** | 32+ vCPU | 256+ ГБ | 2× H100 или эквивалент | 4+ ТБ NVMe | Полный контроль, высокая безопасность, высокая стоимость |

### Итоговые рекомендации для QuantumForge Software

- **Лучший вариант для быстрого внедрения и начального пилота:**  
**Гибридный подход (Вариант B)** — использование облачных API (OpenAI, YandexGPT) для генерации и поиска в сочетании с локальными моделями (Llama 2, Mistral, Qwen) для внутренних задач и хранения чувствительных данных.  
Это позволит быстро показать ценность решения, контролировать безопасность и масштабировать по мере роста.

- **Для масштабных решений и соблюдения требований безопасности:**  
На этапе масштабирования — развертывать локальные модели и базы данных (ChromaDB или FAISS), обеспечивая приватность и стабильность.

- **Поддержка и развитие:**  
Использовать ChromaDB для быстрого прототипирования и тестирования, а при необходимости — масштабировать на FAISS или Milvus для высокой скорости и больших объемов.

**Обоснование выбора:**  
Гибридный сценарий обеспечивает баланс между скоростью, контролем над данными и стоимостью. Использование облачных моделей для быстрого старта и локальных — для долгосрочной эксплуатации и соответствия стандартам безопасности.
